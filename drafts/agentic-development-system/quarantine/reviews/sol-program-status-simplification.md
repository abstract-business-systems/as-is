## Single `tasks.md` assessment

A single achieved/remaining view would improve orientation, but a program-level `tasks.md` is the wrong mechanism. The current task protocol defines each component `tasks.md` as a transient narrative paired with local JSON task authority for one bounded active task; it is removed at completion. Repurposing it as a persistent dashboard would create competing task semantics or a parallel task schema.

Use `handoffs/agentic-development-system.md` as the one canonical durable program-status view because it already declares itself the continuation checkpoint. Keep `handoffs/agentic-development-system-continuity-checklist.md` as a navigation and continuity-verification aid, not another status authority. When implementation tasks exist, the handoff may link to or summarize their authoritative records but must not duplicate or override their statuses.
