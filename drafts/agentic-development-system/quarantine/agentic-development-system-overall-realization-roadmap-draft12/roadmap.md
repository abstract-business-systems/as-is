## Coding/application flow

Terra is the accountable coding/application planning author and implementation adviser. Luna writes application and product code.

1. Terra prepares one bounded coding/application top-level plan with exact scope, dependencies, protected inputs, acceptance, deterministic validation, recovery, escalation, result-review requirements, and current-versus-target treatment.
2. Sol is not directly involved in coding planning, is not a coding-plan reviewer, and is not a coding implementation adviser by default.
3. Terra may optionally consult Sol when architectural advice is needed. If used, record the consultation identity, scope, advice, limitations, Terra’s disposition, and any resulting plan revision.
4. Optional Sol consultation is advisory input only. It does not make Sol an author, co-author, approver, plan reviewer, or implementation adviser.
5. Kimi has no role in coding/application planning, plan review, implementation, implementation advice, validation, result review, integration, or closure.
6. No replacement model plan reviewer is assigned or invented.
7. The human accepts, requests revision, defers, or rejects the exact frozen Terra plan before implementation.
8. A separately authorized kick-off and exact task-control admission are still required.
9. Luna implements only the admitted task. Terra advises within the accepted envelope and cannot silently change scope, architecture, acceptance, protected inputs, risk, or permitted external effects.
10. Terra reviews Luna’s actual result. That review is labelled non-independent because Terra authored the plan and advised implementation.
11. Deterministic validation remains separate. Add independent result review only when risk, architecture, security, external effects, disagreement, or policy requires it.

A design-changing question or material change after Human Review stops affected work and returns it to planning or Human Review. Optional Sol advice does not satisfy a required independent result review.

## Agents/skills flow

Sol is the accountable agents/skills planning author and implementation adviser. Terra implements agent and skill changes.

1. Sol prepares and freezes one bounded agents/skills top-level plan with exact scope, dependencies, protected inputs, acceptance, deterministic validation, migration, recovery, escalation, result-review requirements, and current-versus-target treatment.
2. Sol seeks external Kimi review of that same exact frozen plan. Kimi’s review is advisory and cannot approve the plan or authorize implementation.
3. If Kimi findings cause a material plan change, freeze the successor exact plan and obtain Kimi review of that revision before Human Review.
4. The human accepts, requests revision, defers, or rejects the same exact frozen plan after Kimi review and before implementation.
5. A separately authorized kick-off and exact task-control admission are still required.
6. Terra implements only the admitted agents/skills task. Sol advises within the accepted envelope.
7. Sol reviews Terra’s actual result. That review is labelled non-independent because Sol authored the plan and advised implementation.
8. Deterministic validation remains separate. Add independent result review only when risk, architecture, security, external effects, disagreement, or policy requires it.
9. Kimi is not an implementation-result reviewer by default and is not an integration or completion authority.

The Kimi requirement is limited to this construction exercise’s exact agents/skills top-level plan. It is not a generic target-system gate.
