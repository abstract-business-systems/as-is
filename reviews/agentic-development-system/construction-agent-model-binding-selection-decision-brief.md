# Construction-agent model-binding selection decision brief

## Decision requested

Confirm the construction-only agent/model assignments for the successor implementation packet. This decision concerns candidate implementation agents, not permanent target roles, current workflow replacement, benchmark execution, or contract adoption.

## Correct implementation path

Candidate features are implemented through custom agents explicitly bound to selected model routes. The current `component-builder`, current budget/control implementation, current launcher workflow, and current parent-side integration are not the candidate implementation path. They remain preserved current behavior for later benchmark comparison.

Current task records and the minimum current durable governance needed to protect a construction packet may remain bootstrap records. That governance must not be presented as candidate behavior, and current implementation modules must not be used as the features being realized.

## Required separation

1. The successor packet defines the custom model-bound construction agents and their exact implementation responsibilities.
2. Candidate task-control, reservation, dependency, recovery, and closure structures are implemented through the selected construction flow; the current task-control implementation is not treated as the candidate feature.
3. Current task records and durable governance may protect the construction packet only where required by the accepted authority boundary.
4. The current workflow is invoked only after candidate implementation and candidate proof, as the separately approved benchmark comparison.
5. Deterministic validation, Terra/Sol non-independent result review, any triggered independent review, benchmark scoring, adoption, retirement, and merge remain separate decisions.

## Required gate-time facts

Before a successor packet is frozen, record:

- exact custom agent/profile names and files;
- exact model IDs and provider routes selected by the authorized holder;
- human holders and runtime holders;
- capabilities and tools;
- budgets, reserves, retry and recovery limits;
- protected inputs and deterministic validators;
- implementation-result review scope and any independent reviewer; and
- the bootstrap governance boundary, including exactly which current records may be read or updated without becoming candidate implementation.

If any fact is unavailable, preserve the blocker and do not substitute the current `component-builder`, current budget controls, or a preset alias.

## Human choices

- **Confirm the proposed binding direction:** proceed to prepare the successor packet using custom model-bound Luna/Terra/Sol profiles, subject to exact gate-time identity and capability confirmation.
- **Revise the bindings:** specify different custom profiles, model routes, or ownership.
- **Defer** successor preparation.
- **Reject** the proposed construction-agent model-binding direction.
