## 3. Over-strict findings (question 2)

**(a) Behavioral verification (Gate 4, blocking defect 1) is arguably over-strict for this plan's own artifact form.** The plan deliberately realizes each skill as a *single procedure document* with *no runtime code, no tool registration, no execution engine*. A behavioral test ("an agent following only the candidate skill") presupposes an execution harness the plan explicitly does not build; constructing one would itself be scope expansion beyond the isolated pilot and beyond anything the draft specifies. A static clause-coverage fidelity test plus human side-by-side review is a defensible gate for a document-fidelity pilot. **However** — and this is why I only *qualify* my disagreement — the continuity checklist (sections 4–5) twice requires "behavior diffed against the source-draft contract," and the draft line 88 requires "validation" as distinct evidence. So the review's requirement is grounded in recorded user direction, not invented. My advice: this finding is correct as applied to the *recorded user requirements*, but the review should have said so explicitly and offered the bounded alternative — a small number of scripted scenario walk-throughs (2–3 fixtures per skill, human-evaluated) rather than an unspecified "behavioral test" apparatus. As written, the correction is right in substance but under-specified in remedy.

**(b) The size-check correction (Gate 4, defect 3) is correct and not over-strict.** The plan already half-labels it ("pilot planning target"); the review asks only for consistent labeling. Fine.

**(c) The isolation-mechanics correction (Gate 4, defect 4: worktrees/ephemeral fixtures) is mildly over-prescriptive.** "Other directory absent during test" in a `candidate/` scratch namespace is achievable by testing each skill before the other exists, or in a copied fixture directory; demanding isolated worktrees imports machinery (the repo's worktree launcher) disproportionate to a two-file static-content test. Recommend: require a recorded, reproducible isolation method, not a specific one.
